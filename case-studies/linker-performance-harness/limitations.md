# Limitations

- **Small sample:** five trials per primary route cannot establish a general model ranking.
- **One systems task:** the benchmark stresses Linux process tracing, linker identity, protocol fidelity, and evidence integrity. It does not measure general coding ability.
- **Platform scope:** the workload and verifier are designed for x86-64 Linux and the listed ELF linkers.
- **Route-specific results:** provider path, hosted alias, OpenCode version, tool interface, and date are part of the observed outcome.
- **Mutable hosted systems:** future reruns may differ as providers change aliases, serving behavior, pricing, or caching.
- **Cost accounting:** recorded tokens and cost come from the execution layer and are not normalized across providers.
- **Runtime accounting:** agent time includes tool calls and local compilation work; job-level concurrent execution also overlaps. This is not an inference-latency benchmark.
- **Historical Oracle evidence:** the original successful Oracle is contemporaneously supported, but its raw temporary job directory was not retained. The fresh public-package Oracle is the direct reproducibility record.
- **Task development history:** the five quality checks span multiple digests and two task names. Only the later checks are final-state support; earlier checks document how gaps were found and corrected.
- **Public-package digest:** a private runtime-name comment was rewritten during sanitization, so the public task's file hashes differ from the historical lock digest even though executable behavior is unchanged.
