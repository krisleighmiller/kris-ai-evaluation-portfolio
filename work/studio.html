Generative-AI production suite

Studio

A production system for carrying character identity, voice, and narrative continuity from development through generated media and final assembly.

Role
System design, development, integration, debugging, and evaluation
Stack
Electron, TypeScript, Vite, Rust, JSON-RPC, Atlas Cloud, FFmpeg and ffprobe
Status
Under development · Private source

From production contracts to an integrated application

I began Studio with specialized OpenCode system prompts that defined distinct production roles and their handoffs. That system grew into an integrated desktop application spanning character development, reusable model sheets, scripting, scene planning, still images, video, voice, talking shots, and post-production.

The Electron application uses a TypeScript interface and a Rust host sidecar communicating over stdio JSON-RPC. The Rust dependency set includes reqwest for HTTP integration, Serde for structured data, and YAML serialization for production records. The original standalone Voice Profile Studio uses Tauri rather than Electron.

Continuity is carried by artifacts

  • Character canon: reusable Markdown sheets preserve established identity and appearance. Approved reference-image packs anchor later generation.
  • Voice identity: reference recordings or explicit model-and-voice profiles specify the voice. A generation stage cannot quietly substitute another character’s voice.
  • Narrative integrity: locked source spans, cast, and spoken text carry through scripting and scene planning. Series notes preserve unresolved threads.
  • Visual state: reusable descriptions and opening/closing states connect scenes. Selected out-frames can condition the next video generation when a scene genuinely continues the previous shot.
  • Production handoffs: master Markdown documents and per-scene YAML carry exact speech, assets, generation instructions, and editing requirements between specialists.

Model services and media processing

The originating workflows use Atlas Cloud MCP for model discovery, schema inspection, media upload, and generation. Voice paths distinguish Seed Audio reference-voice generation from catalog voices such as ElevenLabs. Talking shots use reference images and performance audio rather than treating every video model as interchangeable.

FFmpeg and ffprobe provide media inspection, audio padding, trimming, assembly, and caption handling. The workflow preserves actual performance duration rather than blindly trimming every take to an earlier estimate.

Engineering decisions

I defined the production stages, sources of truth, artifact formats, continuity requirements, provider boundaries, and acceptance criteria. Generation records retain prediction IDs and asset status so interrupted work can resume without treating every missing download as a reason to pay for a replacement.

Human creative approval and paid-operation authorization are explicit parts of the workflow. A generated file must be checked as media, not accepted solely because an API returned success.

A separate experiment: autonomous development

After developing and evaluating the system directly, I experimented with autonomous coding agents. For Studio, those experiments did not meet my standard for dependable autonomous development. Passing component checks and confident completion reports did not consistently translate into a usable connected product.

That is a finding about the evaluated development workflows, not the purpose of Studio. The product remains a generative-AI production suite; the autonomy trials are a separate reliability investigation.
