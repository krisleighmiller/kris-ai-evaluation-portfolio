Voice Profile Studio

Create a reusable character voice from an approved recording or a selected model voice, with the audio and technical metadata kept together.

Role
Requirements, application design, development, integration, and evaluation

Relationship
Original voice tool in Studio’s development history

The production problem

A recurring character needs more than a promising voice preview. The selected voice, approved audio, sample text, and model settings need to remain available for later production. I built a dedicated desktop application around that workflow.

Native recording and voice selection

The Rust backend captures audio through PipeWire with an ALSA fallback, writes WAV recordings, and supplies recording-level feedback. The TypeScript interface supports playback, retakes, and saving an approved sample into the character’s voice directory.

A built-in voice browser connects Atlas Cloud voice previews to local playback and selection. Rust handles requests, prediction polling, downloads, WAV conversion, and caching. The API credential is read by the backend rather than supplied to the webview.

Reusable voice assets

Approved samples are saved with character-linked metadata. An existing character reference receives an Audio Profile section; otherwise the application writes a separate YAML profile. Built-in voice metadata preserves the selected model and voice information for subsequent production.

Implementation boundary

This original version uses a bundled English voice catalog and local sample files. The broader design also specifies dynamic catalog synchronization and multi-model voice design; those are distinct from the recording and catalog-preview implementation described here.
