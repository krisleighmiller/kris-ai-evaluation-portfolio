About Miller Applied Systems

An independent practice combining software development, AI evaluation, systems integration, and technical investigation.

The practice

I’m Kris Leigh Miller. I design and develop systems, decide what they need to accomplish, and evaluate whether the result meets those requirements. Miller Applied Systems brings that work together under one professional practice.

My public work includes Link Doctor, a GNU static-link diagnosis tool, and Clip Sleuth, a local clip-source matching application, alongside model benchmarks and technical investigations. Longer-running work includes semantic retrieval, cross-agent knowledge systems, and Studio, a private production-suite experiment. The common thread is practical judgment: understanding the technology well enough to build with it, diagnose it, and recognize when it is the wrong tool.

Technical work

Link Doctor is a Python tool for diagnosing GNU static-library link-order failures. It models symbol demand and archive-member extraction, explains missed providers, and proposes constrained changes to the link command. Optional native-linker verification uses isolated input copies and redirected outputs. The source, examples, tests, and installable package are public.

Clip Sleuth is a local Python CLI and Tk desktop application for matching clips to source videos and timestamps. It uses NumPy, Click, Pydantic, FFmpeg, and ffprobe, with visual matching, separate source and timing diagnostics, paired-frame evidence, resumable batches, and offline reports. The public repository includes an experimental Linux desktop download.

My evaluation work turns requirements into executable checks and controlled comparisons, covering media conformance, linker-performance measurement, clip provenance, professional-report review, and coding-agent reliability. Retrieval investigations examine whether CPU-only indexing and semantic matching justify their time and storage costs. The published studies retain methods, outputs, and findings rather than relying on a model’s description of its own performance.

Hands-on experience across AI development tools

I have extensive hands-on experience working with Claude, Codex, Cursor, Devin, Antigravity, OpenCode, and Hermes. My work spans interactive development, system and workflow design, debugging, integration, and evaluation of agent behavior, including experiments with autonomous development.

This experience informs both how I build systems and how I assess the tools: what they can accomplish, where they fail, and how much human intervention the work actually requires.

Working principles

  • Understand before recommending. Inspect the existing system and reusable tools before proposing another build.
  • Test the real requirement. A successful API call or passing component test is not the same as a usable workflow.
  • Keep the negative findings. An expensive index with poor retrieval or an agent that needs constant rescue is a result worth reporting.
  • Keep authority explicit. Automation does not silently acquire permission to spend, disclose information, or make consequential decisions.
  • Make the reasoning usable. Document decisions, tradeoffs, and limits without burying the conclusion in jargon.
